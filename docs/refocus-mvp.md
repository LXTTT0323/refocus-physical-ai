# RE:FOCUS MVP 定义

> **早期产品定义。** 最终比赛 Demo 已收敛为 Button-PullUp 按钮 + LED1，不使用摇杆；最终闭环以根目录 README 为准。

## 一句话

RE:FOCUS 是保护工作上下文的桌面 Physical AI Agent：当用户被打断或离开工作现场时，它保存“做到哪里、下一步是什么”，并在用户回来后帮助他快速回神。

## 第一目标用户

经常在电脑前进行复杂创作、开发或知识工作的个人，尤其是容易被会议、消息和临时事务打断的人。

## 唯一核心闭环

```text
用户语音声明当前目标
→ 电脑端记录最小任务上下文
→ 按键/在席信号触发离席或中断
→ Agent 生成结构化 Checkpoint
→ 用户回来触发恢复
→ 独立设备通过眼睛、文字、语音或震动给出下一步
```

## 三分钟 Demo 的魔法瞬间

用户正在修改比赛方案，临时离开。设备进入守护状态并保存 Checkpoint。用户回来按下设备，设备“醒来”并说：

> 你刚才在完善 RE:FOCUS 的演示流程，已经确定了中断恢复闭环。下一步是补上设备震动反馈。

随后电脑端直接展示对应任务和保存证据。

## MVP 必做

- 用户通过语音或按钮声明一个当前目标。
- 读取当前应用名、页面标题、空闲/在席状态中的至少两项。
- 完成一次离席或中断事件。
- Agent 生成包含 `goal`、`progress`、`next_action` 的 Checkpoint。
- 用户回来后，真实硬件完成至少一种可观察输出。
- TiDB/Agent Stack 保留本次状态和脱敏 Trace。
- 同一脚本连续演示三次成功。

## 暂时不做

- 持续上传摄像头或完整屏幕视频。
- 医疗诊断、ADHD 治疗或生产力评分。
- 企业员工监控、管理者排行榜。
- 同时开发桌面主机和第二个穿戴设备。
- 复杂自动操作电脑、关闭应用或强制阻止访问。
- 长期习惯分析、音乐生成和多套人物性格。

## 形态决定

- 比赛版：一个独立桌面设备 + 一个电脑端观察器。
- 唯一目标板为 C 板：电脑摄像头本地判断在席/头部方向，C 板优先接入 PIR、距离与用户按键，并用 GPIO48 RGB 灯和 LCD/OLED 输出状态。
- C 板摄像头作为第二阶段：先用现成 `gc2145-camera` 独立验证摄像头、LCD、快照和灯光；由于默认引脚冲突，不与全部传感器同时承诺。
- 未来版：核心设备可从桌面底座拆下夹在衣服上；不纳入本次必要交付。

## 隐私原则

- 用户主动开始和结束一个专注 Session。
- 原始屏幕和摄像头数据默认不上传。
- 优先上传结构化事件，不记录键盘内容和私人消息正文。
- 设备持续显示感知状态，并提供物理静音/隐私开关。
- 用户可以查看、修改和删除 Checkpoint。

## 下一步验证顺序

1. 确定能拿到的板卡，首选 A、保底 D。
2. 跑通屏幕/灯光、按钮、声音或震动中的“一入一出”。
3. 跑通 Agent Stack 的单次 Session/Turn。
4. 用手动离开/回来事件完成第一条端到端闭环。
5. 再接入浏览器标题、应用名和空闲状态。
6. 最后增加眼睛动画、语音表达和演示外壳。
