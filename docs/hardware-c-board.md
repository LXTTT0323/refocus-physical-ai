# C 板完整核对与 RE:FOCUS 落地方案

> 核对日期：2026-08-28。实际领用硬件已确认为 **C 板：ESP32-S3 AIoT 全功能套件**。本页以比赛官方赛前说明、厂商硬件文档和当前锁定的 Agent_link 源码交叉核对；若现场实物丝印或电路版本不同，以实物和现场口径为准。

## 1. 硬件身份与定位

- 主控：ESP32-S3，双核 MCU，支持 2.4 GHz Wi-Fi 与 BLE 5。
- 尺寸：PCB 约 250×175 mm，安装孔距约 244×169 mm。
- 电平：模块逻辑电压 3.3V；外部供电按指定电源入口使用 6–12V，绝不能把该电压接入 GPIO。
- 显示：1.3 英寸 ST7789 LCD，另有 SSD1306 OLED 模块。
- 媒体：GC2145 摄像头、数字麦克风、I2S 功放。
- 扩展：排针与 Grove 接口。
- 官方表述同时出现“21 类模块”“27 个子模块”和“21 种模块 + 1 块主控集成板”，计数口径不完全一致；项目不把模块数量作为功能承诺。
- 官方定位：多传感器融合、环境感知和互动装置；开发难度中高。

## 2. 模块清单

官方/厂商资料列出的能力包括：

1. 摇杆；
2. INA219 电流检测；
3. 电机驱动；
4. BMI270 六轴 IMU；
5. 光照传感器；
6. MQ2 烟雾传感器；
7. DHT11 温湿度；
8. 1.3 英寸 ST7789 LCD；
9. SSD1306 OLED；
10. 热敏电阻；
11. 音频功放；
12. 旋转编码器；
13. 电位器；
14. MicroSD；
15. VL53L0X 激光测距；
16. 数字麦克风；
17. PIR 人体红外；
18. LED；
19. 蜂鸣器；
20. 上拉按键；
21. 下拉按键；
22. 摄像头；
23. ESP32-S3 核心板及传感器扩展底板。

现场不提供电机，且禁止焊接，所以电机运动不进入 RE:FOCUS 比赛 MVP。

## 3. 官方固定外设引脚

| 外设 | 引脚 |
| --- | --- |
| ST7789 LCD | SCL=GPIO21，SDA/MOSI=GPIO47，DC=GPIO43，CS=GPIO44 |
| I2S 功放 | LR=GPIO40，BCLK=GPIO39，DIN=GPIO38 |
| MicroSD | MISO=GPIO35，CLK=GPIO3，MOSI=GPIO14，CS=GPIO46 |
| 数字麦克风 | WS=GPIO42，SD=GPIO2，SCK=GPIO41 |
| GC2145 摄像头控制 | SDA=GPIO4，SCL=GPIO5，XCLK=GPIO15 |
| GC2145 摄像头同步 | VSYNC=GPIO6，HREF=GPIO7，PCLK=GPIO13 |
| GC2145 摄像头数据 | Y9=16，Y8=17，Y7=18，Y6=12，Y5=10，Y4=8，Y3=9，Y2=11 |
| 板载 WS2812 | GPIO48 |

当前 Agent_link 的 `gc2145-camera` 适配还把 GPIO3 作为主动高电平的拍照按钮。

## 4. 常见模块示例引脚与冲突

厂商示例给出的常见接法：

| 模块 | 示例引脚 | 与摄像头/固定外设的关系 |
| --- | --- | --- |
| 摇杆 | X=1，Y=2，按键=3 | GPIO2 与数字麦克风冲突；GPIO3 与 SD CLK/拍照按钮冲突 |
| LED / 蜂鸣器 | GPIO9 | 与摄像头 Y3 冲突，且两模块彼此也冲突 |
| 光照 | GPIO18 | 与摄像头 Y7 冲突 |
| 电位器 | GPIO13 | 与摄像头 PCLK 冲突 |
| DHT11 | GPIO8 | 与摄像头 Y4 冲突 |
| MQ2 | 模拟=15，数字=14 | 与摄像头 XCLK、SD MOSI 冲突 |
| 热敏电阻 | 模拟=5，数字=4 | 与摄像头 SCCB SCL/SDA 冲突 |
| PIR | GPIO16 | 与摄像头 Y9 冲突 |
| 编码器 | CLK=6，DT=7，按键=8 | 与摄像头 VSYNC/HREF/Y4 冲突 |
| 上拉/下拉按键 | GPIO12 / GPIO14 | 分别与摄像头 Y6、SD MOSI 冲突 |

结论：**不能照搬所有示例接线，同时启用摄像头和全部传感器。** 先选工作模式，再决定是否把可移动模块重映射到空闲 Grove/排针；任何重映射都必须根据实物丝印和原理图逐项验证。

VL53L0X、INA219、BMI270 属于 I2C 类模块；其实际总线引脚和地址需在真机接入前由实物文档、示例源码或 I2C 扫描确认，当前不猜测。

## 5. Agent_link 的真实支持范围

锁定源码提交 `3c93ecfcdc473c952a0e85d9797c2663e9ba7d87` 中，没有“C 板全部模块”的完整适配。现成可选项是：

```text
idf.py menuconfig
→ Agent Link Device
→ Board Type
→ ESP32-S3 GC2145 Camera (DVP camera preview on ST7789 LCD)
```

该适配已经实现：

- GC2145 以 RGB565、240×240 双缓冲采集；帧缓冲位于 PSRAM；
- ST7789 实时本地预览；
- 把单帧编码为 JPEG，通过 Agent_link 图片通道发送；
- `camera0` 快照端点；
- GPIO3 拍照按钮；
- GPIO48 板载 WS2812，暴露为 `led0`；
- 能力声明为 `CAMERA | SCREEN | LED`。

它尚未声明或实现 C 板的 PIR、VL53L0X、摇杆、编码器、BMI270、麦克风、功放等完整能力。要加入这些能力，需要扩展/新建 C 板适配，并在 Kconfig、CMake 与 I/O 端点中注册。

此外，当前源码支持的是**单张快照上传**，不是可依赖的连续云端视频流；Wi-Fi 通道也不能在真机验证前作为比赛基线。

## 6. 对 RE:FOCUS 最合理的使用方式

C 板应定位为桌面“状态锚点 + 人体辅助传感器”，电脑仍负责最可靠的工作上下文检测。

### 比赛 MVP：传感器优先模式（推荐）

- 电脑端：前台窗口、标题/项目相关性、文件保存与真实进展、电脑摄像头的人脸/头部方向。
- C 板输入：PIR 检测人体存在；VL53L0X 检测坐席距离/回来；摇杆或按键完成开始、结束、确认恢复。
- C 板输出：GPIO48 RGB 灯显示状态；LCD/OLED 显示目标、`已保存断点`、`下一步`；蜂鸣器/语音后置。
- Agent Stack：只在开始、中断、回来、结束等关键节点理解任务并生成 Checkpoint/恢复话术。

这样能形成真正的交叉验证：

```text
电脑任务窗口 + 成果进展
        ×
电脑摄像头在席/头部方向
        ×
C 板 PIR + 距离 + 用户按键
→ 本地状态机
→ Agent Checkpoint
→ C 板灯光/屏幕恢复提示
```

### 摄像头优先模式（第二阶段）

先直接编译官方 `gc2145-camera`，验证摄像头、LCD、快照和 WS2812。它适合做视觉展示，但默认引脚下无法同时照搬多种传感器示例。若决定保留 C 板摄像头，应只增加经过重映射验证且无冲突的少量输入。

### 为什么比赛 MVP 不把 C 板摄像头作为主人体检测

- 官方现成适配能预览和拍照，但没有人脸/头部/眼睛/哈欠识别；
- ESP32 端持续视觉推理会增加性能和联调风险；
- 默认摄像头引脚与 PIR、编码器、DHT11、光照等模块大量重叠；
- Windows 摄像头更适合本地输出 `present/facing_workspace/yawn_candidate` 等结构化信号，C 板则提供独立的 PIR/距离证据和物理反馈。

眼睛注视、哈欠只能作为低权重辅助信号，不能单独证明进入心流，也不能用于医疗判断。

## 7. 最短真机验收顺序

1. 拍摄板卡正反面和丝印，确认具体版本、USB 口、电源入口、跳帽/拨码与可用模块。
2. 只用 USB 供电，确认串口号、芯片和 Flash/PSRAM；暂不接 6–12V 外电源。
3. 使用 ESP-IDF v5.5.4 编译并烧录 `gc2145-camera`，先验收 LCD、摄像头和 GPIO48 RGB 灯。
4. 若走推荐的传感器优先模式，建立 `refocus-c-board` 适配；先接一个用户按键和 RGB 状态灯。
5. 单独验证 PIR，再单独验证 VL53L0X；输出统一的结构化事件。
6. 接入 Windows Bridge，验收 `SESSION_START → INTERRUPTION → SESSION_RESUME → SESSION_END`。
7. 最后才添加屏幕文案、音频、编码器或更多传感器。

每增加一个模块都要记录：引脚、驱动、采样率、事件阈值、与其他外设的冲突、断开后的降级路径。

## 8. 尚待实物确认

- C 板具体硬件修订版本和摄像头实际 PID；
- Grove/排针是否允许安全重映射，以及板上是否存在选择开关/跳帽；
- VL53L0X、INA219、BMI270 的实际 I2C 引脚、地址和总线共享方式；
- LCD 与 OLED 是否能同时启用；
- 板上各模块是固定连接还是需要跳线连接；
- USB 供电是否足以支持选定模块组合；
- Agent_link BLE 图片/事件链路在现场手机与固件上的实际稳定性。

这些不是方案阻塞：MVP 可以从按键 + GPIO48 灯 + 电脑端检测开始，再逐项增加 C 板传感器。
