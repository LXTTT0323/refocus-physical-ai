# RE:FOCUS 产品决定与历史选题分析

> 2026-08-27 决定：正式选择 RE:FOCUS。下方 AI Game Master 内容仅作为历史分析，不再进入开发排期。

## 共同判断原则

两个方案都不能做成“LLM 套壳”。选择时应优先比较：

- 三分钟内是否有一个直观、连续的魔法瞬间。
- 硬件是否不可替代。
- Agent 是否做了真正的上下文判断或持续任务。
- 是否能把隐私、权限和安全讲清楚。
- 当前两到三人的队伍是否真的能完成。

## 历史备选：AI Game Master

### 产品定义

线下游戏的 Agent 操作系统。首个规则包是狼人杀，长期扩展到阿瓦隆、血染钟楼、剧本杀、D&D、团建和婚礼互动。

### 魔法瞬间

一名玩家离席，游戏继续。玩家回来后，系统根据其身份和已知信息生成一段不泄密的个性化补课；游戏结束后，每个人收到不同的个人复盘。

### 为什么需要硬件

- 桌面中央需要一个所有人共同认可的主持与规则权威。
- 屏幕、灯光和声音让游戏阶段在空间中可见。
- 摄像头/按钮/麦克风或玩家手机提供真实输入。
- 私密信息在个人手机，公共状态在桌面设备，形成空间上的信息边界。

### MVP

- 三人最小流程或一段完整日/夜流程。
- 手机加入座位并标识说话人。
- 桌面设备完成一次公开主持和阶段反馈。
- 一次离席、回归和权限安全摘要。
- 一局结束后的个人复盘。

### 最大风险

- 多人语音和网络容易影响现场稳定性。
- 如果硬件只播放网页已有结果，会被质疑为软件外壳。
- 游戏向善价值需要主动解释：无障碍加入、降低规则门槛、减少主持负担、公平信息恢复，而非只强调娱乐。

## 正式方案：回神 RE:FOCUS

### 产品定义

保护工作上下文的桌面/可穿戴 Agent。它不负责监工，而是识别“我原本想完成什么”，在中断时保存现场，并在回来时还原下一步。

### 魔法瞬间

用户离开电脑后，Agent 自动生成 Checkpoint；用户回来，设备睁眼/提示并恢复：“你刚才在改第 4 页，下一步是补 TiDB 的记忆闭环。”

### 为什么需要硬件

- 独立眼睛/屏幕让 Agent 状态与隐私状态持续可见。
- 声音、灯光或触觉反馈不占用手机和电脑通知区。
- 桌面底座对应工作场景；可拆卸夹子对应离开电脑后的提醒。

### MVP

- 语音声明一个当前目标。
- 电脑端观察当前应用/网页和用户在席状态。
- 判断一次相关活动与一次明显跑偏/离席。
- 保存当前文件、进度和下一步。
- 用户回来后由设备给出反馈并恢复上下文。

### 最大风险

- D 板屏幕和震动需要补底层实现。
- 自动理解屏幕、人在不在和任务相关性会同时增加开发量。
- 必须避免“员工监控”印象，默认本地处理并明确隐私模式。

## 基于官方评分的当前比较

| 维度 | AI Game Master | RE:FOCUS |
| --- | --- | --- |
| 创新性 | 平台化、权限安全补课和个人复盘有差异；但 AI 主持较常见 | “保护思路而非封锁分心”更原创 |
| 向善价值 | 需要用包容、公平、无障碍和降低主持门槛来建立 | 心流、中断恢复、认知负担与隐私保护更自然 |
| 落地完成度 | 已有多人 Web 基础，较强 | 设备固件、桌面观察和自动恢复同时存在，较弱 |
| 现场吸引力 | 多人互动、声音与灯光非常强 | 魔法瞬间清楚，但需要精心编排才能被看见 |
| 硬件理由 | 必须做成公共桌面中枢，不能只是扬声器 | 桌面/可穿戴形态与物理反馈理由充分 |

## 最终决定

正式选择 RE:FOCUS，理由是它在创新性、向善价值和硬件不可替代性上更统一，也更贴合团队希望探索的个人成长方向。

开发边界：比赛只证明一次可靠的“中断恢复”，不同时解决全自动屏幕理解、疲劳诊断、习惯养成、专注音乐和跨设备穿戴等所有问题。
